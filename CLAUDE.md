# Cheese

Cheese is a native macOS menu bar utility that combines five tools:
1. **Clipboard history** (replaces Maccy)
2. **Screenshots**: region, window and full screen, via ScreenCaptureKit
3. **OCR**: copy text, QR codes and barcodes from any region (replaces TextSniper)
4. **Scrolling screenshots**: auto-scroll, stitch, preview
5. **Window snapping**: Windows-style arrow-key arrangement

Goals: a fast, reliable daily driver for the author, released as an open-source project on GitHub (MIT).

---

## Platform & stack

- **Target:** macOS 27 only (deployment target `27.0`). Use the newest APIs freely; add no availability checks or fallbacks for older macOS.
- **Language:** Swift 6 language mode, strict concurrency on. UI code is `@MainActor`; heavy work (stitching, OCR, file I/O) runs off the main actor.
- **UI:** SwiftUI for views. AppKit for anything SwiftUI can't do: `NSStatusItem`, `NSPopover`/`NSPanel`, borderless overlay windows, and `NSPasteboard`.
- **Project:** generated with **XcodeGen** from `project.yml`. **Never hand-edit `Cheese.xcodeproj`.** Change `project.yml` and run `make generate`.
- **App type:** `LSUIElement = YES`, so there's a menu bar icon and no Dock icon. **Not sandboxed**, because Accessibility access and posted keyboard/scroll events don't work inside the sandbox.
- **Dependencies (Swift Package Manager), and only these unless the author approves another:**
  - `KeyboardShortcuts` (sindresorhus): global hotkeys plus the rebinding UI in Settings
  - (no others in v1)

| Technology | Used for |
|---|---|
| NSPasteboard | Polling `changeCount` every ~0.5 s for clipboard changes |
| SwiftData | Clipboard history (200 items, pins). Image and file payloads live on disk, not in the store |
| ScreenCaptureKit (`SCScreenshotManager`, `SCShareableContent`) | All screen capture. Cheese's own overlay windows must be excluded from every capture |
| Vision | Text recognition, barcode/QR detection, frame registration for stitching |
| Accelerate / vImage | Fast row comparison for stitching and sticky-header detection |
| CGEvent | Synthesized Cmd+V (paste from history) and scroll-wheel events (auto-scroll) |
| Accessibility (`AXUIElement`) | Moving and resizing other apps' windows |
| SMAppService | Launch at login |

## Feature spec

### 1. Clipboard history
- **Records:** plain text, rich text/HTML/RTF (keep every representation so items paste back with formatting), images (PNG on disk under `~/Library/Application Support/Cheese/Images/`), and files/folders (stored as file URLs, not copies).
- **Monitoring:** poll `NSPasteboard.general.changeCount`. Skip consecutive duplicates. Re-copying an existing item moves it to the top instead of duplicating it.
- **Privacy:** **skip** any pasteboard item carrying `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType` or `org.nspasteboard.AutoGeneratedType`, which is how password managers mark secrets. No other privacy features in v1.
- **Retention:** keep the last **200 unpinned** items. Pinned items don't count toward the limit and never expire. Delete orphaned image files when their item is removed.
- **Persistence:** history survives quit and reboot.
- **Clear:** menu bar menu has **"Clear History"** (removes unpinned items) and **"Clear All"** (removes everything, with a confirmation dialog).
- **Panel:** opens as a popover **anchored under the menu bar icon** (from the hotkey or the menu's *Clipboard History* item; clicking the icon itself opens the menu). Two-column layout: list on the left, **preview pane** on the right (full text, rendered rich text, image preview, or file icon and path).
- **Search:** type-to-filter fuzzy matching over item text, **including text recognized in image items** (see OCR → Live Text). 200 items is small, so use an in-memory fuzzy scorer in a pure, unit-tested function. No search index needed.
- **Paste flow (important):** record the frontmost app **before** opening the panel. On selection: write the item to the pasteboard, close the panel, re-activate the recorded app, wait for activation, then post Cmd+V with `CGEvent`. Needs Accessibility permission. If it's missing, copy only and show the permission prompt (see Permissions).

### 2. Screenshots
- **Modes:** region (drag a rectangle over a frozen overlay on every display), full screen (display under cursor), window (hover highlights a window, click captures it with its shadow).
- **Default result:** **copy to clipboard only**, plus a brief toast. Nothing is written to disk.
- **Editor path:** holding **Shift when finishing the capture** (mouse-up in region mode, click in window mode, or Shift held with the full-screen hotkey) opens the **annotation editor** instead.
- **Annotation editor (basic):** arrow, rectangle, text, highlighter, blur/pixelate, crop, undo/redo. Buttons: **Copy**, **Save** (PNG), **Close**.
- **Saving:** PNG, named `Cheese YYYY-MM-DD at HH.mm.ss.png`. Save folder is configurable in Settings (default `~/Desktop`).
- Retina-correct: capture at native backing scale. Never downscale silently.
- Not in v1: repeat last region, auto-save, floating thumbnail.

### 3. OCR
- `Ctrl+Opt+T` → region overlay → recognize text with Vision (accurate level, language correction on) → **copy text + toast** ("Copied 42 words").
- **Languages:** English and Hindi. ⚠️ Check `supportedRecognitionLanguages` at runtime. If Hindi isn't supported on this macOS, show it as unavailable in Settings instead of failing silently. Verify this early.
- **Line breaks:** Settings toggle, *Keep line breaks* (default on) or *Join into paragraphs*.
- **QR / barcodes:** detect barcodes in the same region. If any are found, copy their payload instead of the text, and if it's a URL the toast offers "Open".
- **Live Text on history images:** after an image item enters history, OCR it in the background at low priority and store the text on the item so search can match it. OCR failure must never block or break the clipboard.

### 4. Scrolling capture
- `Ctrl+Opt+S` → choose a region over the scrollable content → Cheese **auto-scrolls** with synthesized scroll-wheel events, capturing a frame after each step.
- **Vertical only.**
- **Stops** on Esc/Return, or automatically when consecutive frames are identical (end of page). Enforce a maximum output height (e.g. 30,000 px) to protect memory.
- **Stitching:** find each new frame's vertical offset against the previous one (vImage row hashing first, Vision translational registration as a fallback) and append only the new rows.
- **Sticky headers/footers:** **auto-detect** rows that stay identical at the top or bottom of every frame, keep them once, and exclude them from offset matching.
- **Result:** opens a **preview window** (scrollable) with **Copy**, **Save**, **Annotate** and **OCR** buttons.
- `Stitcher` and `StickyRegionDetector` must be **pure functions over image buffers** with unit tests driven by fixture images in `CheeseTests/Fixtures/`.

### 5. Window snapping
- Acts on the **focused window of the frontmost app** through `AXUIElement`.
- **Positions:** left half, right half, maximize, bottom half, restore.
- **Repeat press:** pressing `Ctrl+Opt+→` while the window is already on the right half moves it to the **left half of the next display to the right** (and the mirror case for `←`), like Windows. On the last display, do nothing.
- **Restore:** before the first snap, remember each window's original frame (keyed by app PID plus AX window identity). `Ctrl+Opt+Delete` returns the window to that frame.
- Use `NSScreen.visibleFrame` so the menu bar and Dock are respected. No gaps, no drag-to-edge snapping.
- ⚠️ **Coordinate systems:** AX uses a top-left origin on the primary display, while AppKit uses bottom-left. Put all conversion in `DisplayGeometry` and unit-test it with multi-display layouts, including displays above, below and left of the primary.
- Some windows refuse resizing (fixed-size panels). Clamp the frame and don't crash.

### Menu bar menu
Any click on the icon opens this menu, so every feature works without hotkeys. Items show their current hotkey and an SF Symbol.

Clipboard History · — · **Capture:** Capture Region · Capture Window · Capture Full Screen · Scrolling Capture · — · **Text:** Copy Text from Screen · — · **Windows:** Arrange Window ▸ (Left Half · Right Half · Maximize · Bottom Half · Restore Previous Size) · — · Clear History · Clear All… · — · Keyboard Shortcuts… (opens Settings on the Shortcuts tab) · Settings… · Welcome Guide… · — · Quit Cheese

### Settings (SwiftUI window)
- **General:** launch at login, screenshot save folder, "Show Welcome Guide…"
- **Shortcuts:** `KeyboardShortcuts.Recorder` for every action
- **Clipboard:** history size (default 200)
- **OCR:** languages, line-break mode
- **Permissions:** live status of Screen Recording and Accessibility, each with an "Open System Settings" button

### Welcome guide
Shown once on first launch (`hasSeenWelcome` in UserDefaults; closing it counts as seen), reopenable from the menu (Welcome Guide…) and Settings → General. Four pages: what Cheese does (with live shortcuts) · permissions (live status + Open System Settings) · shortcuts (the same recorders as Settings) · launch at login. Everything in it is skippable.

### Permissions
- Besides the welcome guide, when a feature needs a permission that's missing (Screen Recording for capture/OCR/scroll, Accessibility for paste/snap/auto-scroll), show a single clear alert explaining why, with a button that opens the right System Settings pane.
- Check with `CGPreflightScreenCaptureAccess()` and `AXIsProcessTrusted()`. Never call the request APIs in a loop.

## Architecture

```
Cheese/
  App/            CheeseApp, AppDelegate, MenuBarController, StatusMenu
  Core/           Hotkeys (KeyboardShortcuts names), Permissions, Toast, DisplayGeometry
  Clipboard/      PasteboardMonitor, ClipItem (SwiftData), ClipStore, FuzzyMatcher,
                  HistoryPopover + views, Paster
  Capture/        CaptureService (ScreenCaptureKit), SelectionOverlay, WindowPicker
  Editor/         AnnotationEditor window, tools, canvas model
  OCR/            TextRecognizer, BarcodeReader, LiveTextIndexer
  ScrollCapture/  ScrollCaptureSession, AutoScroller, Stitcher, StickyRegionDetector,
                  ScrollPreviewWindow
  Windows/        WindowManager (AX), SnapLayout (pure frame math), FrameHistory
  Settings/       SettingsView + tabs
  Welcome/        First-launch welcome guide
CheeseTests/      Unit tests + Fixtures/
project.yml       XcodeGen spec
Makefile
```

Rules:
- Keep pure logic (FuzzyMatcher, Stitcher, StickyRegionDetector, SnapLayout, DisplayGeometry, retention rules) **free of AppKit/system calls** so it's unit-testable.
- System APIs sit behind small protocols (`PasteboardReading`, `ScreenCapturing`, `WindowControlling`) so tests can substitute fakes.
- Each feature module talks to others only through `App/` wiring. Clipboard must not import ScrollCapture, and so on.
- No force-unwraps or `try!` outside tests. Log with `os.Logger` (subsystem `com.maanitgupta.cheese`, one category per module).

## Commands
```
make generate   # xcodegen generate
make build      # xcodebuild -scheme Cheese -configuration Debug build
make test       # xcodebuild test -scheme Cheese
make run        # build, then open the .app
make release    # Release build zipped to dist/Cheese.zip (+ .sha256) via scripts/package.sh
```

After every change: `make build` must succeed with **zero warnings**, and `make test` must pass.

## Signing during development
Sign Debug builds with the author's stable **Apple Development** identity (a free Apple ID personal team is fine; set it in `project.yml`). macOS ties Screen Recording and Accessibility grants to the signature, so ad-hoc or changing signatures force re-granting permissions on every build. Don't change the bundle ID (`com.maanitgupta.cheese`) or signing settings without asking.

## Things only the author can verify
Claude Code can build and unit-test but can't grant TCC permissions or judge on-screen behavior. When a task touches overlays, hotkeys, pasting, snapping or scrolling capture, end with a short **manual test checklist** for the author (multi-display, Retina vs non-Retina, full-screen Spaces, Safari/Chrome/Slack/Notes for scrolling capture).

## Suggested build order
1. App shell: menu bar item, menu, Settings window, hotkey registration, permissions helper
2. Clipboard history end to end, including the paste flow
3. Capture service + region/window/full-screen + toast
4. OCR (+ QR) on top of the region overlay; Hindi support check
5. Window snapping + DisplayGeometry tests
6. Annotation editor
7. Live Text indexing of history images
8. Scrolling capture (stitcher tests first, using fixtures)

## Release (v1)
GitHub Releases with a zipped `Cheese.app` (never a .dmg), unnotarized.
